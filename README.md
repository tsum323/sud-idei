# AI COURT

Личный AI-суд для идей. Девять AI-агентов независимо рассматривают идею, проводят один раунд
перекрёстной критики, а главный судья выносит вердикт: допустить к реализации, допустить
условно, отправить на доработку или отправить в «Тюрьму идей».

Всё происходит на одном пиксельном экране: нажимаете на персонажа и читаете его заключение.

## Быстрый старт

Нужны **Node.js 22.13 или новее** (хранилище работает на встроенном `node:sqlite`) и ключ Claude API.

1. Создайте ключ в [Claude Console](https://console.anthropic.com/) (раздел API Keys) и пополните
   баланс в Billing. **Подписка Claude Pro или Max не даёт доступа к API**: API оплачивается
   отдельно, по токенам.
2. Установите зависимости и укажите ключ:
   ```bash
   npm install
   cp .env.example .env.local
   # откройте .env.local и впишите ANTHROPIC_API_KEY=sk-ant-...
   ```
3. Запустите:
   ```bash
   npm run build && npm start   # http://localhost:3000
   # или для разработки: npm run dev
   ```

Пока ключ не задан, приложение открывается, но вместо запуска заседания показывает инструкцию
по настройке. Подставных или шаблонных заключений нет.

Проверки:

```bash
npm test           # тесты (vitest), в сеть не ходят
npm run typecheck  # tsc --noEmit
```

## Модель и стоимость

```
AI_MODEL=claude-opus-5-5   # или claude-sonnet-5-5 — примерно вдвое дешевле
AI_EFFORT=medium           # low | medium | high | xhigh | max
```

Одно полное заседание — это 11 вызовов модели (9 агентов + критика + судья). По грубой оценке это
порядка 40–60 тыс. входных и 30–50 тыс. выходных токенов, то есть **около $1 на Opus 5.5 и около
$0.5 на Sonnet 5.5**. Реальная цифра зависит от длины описания и уровня effort: точный расход
смотрите в Claude Console → Usage. Перед каждым платным запуском приложение спрашивает
подтверждение; это можно отключить в настройках ⚙.

`AI_FALLBACKS=on` включает серверный fallback Anthropic (`fallbacks: "default"`): если
классификатор безопасности отклоняет запрос, API повторяет его на другой модели в рамках того же
вызова. Чтобы отключить, поставьте `off`.

Ключ читается только серверным кодом. Модули `src/server` импортируют `server-only`,
`/api/settings` ключ не возвращает, а тест проверяет, что клиентский код не обращается ни к
`process.env`, ни к серверным модулям. `.env.local` добавлен в `.gitignore`.

### Веб-поиск (необязательно)

```
SEARCH_PROVIDER=tavily
TAVILY_API_KEY=tvly-...
```

Перед анализом выполняются три поисковых запроса: конкуренты, цены, рынок. Найденные источники
сохраняются как доказательства E1, E2… со ссылкой и датой проверки. Агент может назвать
утверждение «фактом», только сославшись на существующее доказательство. Если ссылки нет, код
понижает утверждение до «предположения». Без поиска отчёт и вердикт прямо указывают, что
актуальные данные не проверялись.

## Как устроено

```
src/
  app/                 Next.js (App Router): страница и API-маршруты
    api/cases/...      создание дела, этапы, вердикт, пересмотр, архив
  components/          интерфейс: сцена, персонажи (SVG-спрайты), панели
  client/              клиентский API и хук управления заседанием (useCourt)
  shared/              общий код: схемы (zod), критерии, расчёт оценок,
                       план заседания, нормализация ответов, построение отчёта
  server/
    ai/                адаптер провайдера: интерфейс, Anthropic, ошибки, повторы
    agents/roles.ts    инструкции 9 ролей
    judge/judge.ts     главный судья
    court/             оркестратор процесса и промпты
    evidence/          адаптер веб-поиска
    db/                SQLite-схема и репозиторий
tests/                 тесты vitest; tests/fixtures — тестовый провайдер без сети
```

**Ход заседания.** Каждый этап — отдельный POST-запрос, который клиент вызывает по явному
действию пользователя:

1. `evidence`: веб-поиск, если он настроен.
2. `agents/:agentId`: девять независимых анализов. Клиент запускает их параллельно, по умолчанию
   по три одновременно (меняется в настройках). Результат сохраняется сразу после ответа
   агента. Состояние «Готов» ставится только после сохранения.
3. `cross-exam`: один вызов находит до четырёх самых важных противоречий и оформляет
   контраргументы от лица подходящего агента.
4. `verdict`: судья получает заключения, итоги критики, доказательства и сводку баллов. Общий
   балл считается в коде как взвешенное среднее 10 критериев. Модель выносит решение и объясняет
   вес аргументов. Формальный ориентир по баллам передаётся ей только как справка: одна низкая
   оценка сама по себе не ведёт к отклонению.

**Надёжность.**
- Ошибка одного агента не трогает остальных: агента можно перезапустить отдельно.
- Готовый результат без явного `force` не пересчитывается.
- Повторный одновременный запуск того же агента сервер отклоняет.
- Временные ошибки (429, 5xx, сеть, тайм-аут, неверный JSON) повторяются ограниченное число
  раз (`AI_MAX_RETRIES`). Ошибки ключа и отказы модели не повторяются.
- Вызов, который завис после перезапуска сервера, помечается как прерванный, и его можно
  повторить.
- Кнопка «Продолжить заседание» выполняет только незавершённые этапы.
- Если часть агентов завершилась ошибкой, вердикт выносится только по явной кнопке и
  помечается как предварительный.
- Фоновых вызовов модели нет. Пока на сервере идёт вызов, клиент опрашивает только хранилище.

**Хранение.** SQLite-файл `./data/ai-court.db` (путь задаётся в `DATABASE_PATH`). Таблицы:
`cases`, `agents`, `agent_analyses`, `evidence`, `cross_examinations`, `verdicts`,
`action_plans`, `case_events`, `case_stages`. Сущности из ТЗ сохранены, добавлены `round` (номер
заседания) и `case_stages` (состояние этапов для продолжения заседания). Архив и отчёт читаются из
базы, модель для этого не вызывается.

**Тюрьма идей и пересмотр.** Вердикт «Отклонена» переводит дело в статус `prison`. Дело и все
материалы при этом сохраняются. Вернуть идею на пересмотр можно только с описанием новых
оснований, не короче 20 символов. Пересмотр открывает новое заседание (`round + 1`), а прошлые
вердикты остаются во вкладке «История».

## Ограничения

- Полное заседание с действующим ключом в среде разработки не запускалось: ключа не было.
  Проверено, что запрос доходит до API Anthropic (неверный ключ даёт понятную ошибку 401 в панели
  агента), а форма запроса и разбор ответа покрыты тестами на подменённом HTTP. Первое
  заседание с вашим ключом — фактически приёмочный тест.
- Общий балл — ориентировочная оценка модели, а не вероятность успеха. Вероятности приложение не
  показывает.
- Веб-поиск реализован только для Tavily. Другой поисковик подключается через интерфейс
  `SearchProvider` в `src/server/evidence/search.ts`.
- Приложение рассчитано на локальный запуск для одного пользователя: авторизации нет. Не
  публикуйте его в интернет как есть, иначе кто угодно сможет тратить ваш API-баланс.
- `node:sqlite` в Node 22 выводит предупреждение `ExperimentalWarning`. Это ожидаемо и на работу
  не влияет.
